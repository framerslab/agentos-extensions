`GitHubDocumentsConnector` refuses, before any request, what it cannot answer whole. `changesSince` takes exactly one repository a call: it compared only the first id of a selection and answered a cursor that stood for that repository alone, so the other repositories' changes were never reported. It also refuses an empty `after`, and a `listing` passed without the `after` commit it was read at, whose files it labelled with the head it read in its place. `list` checks every selected id before it reads any repository, and refuses a repository named twice. A repository id must be a positive integer in decimal: `077`, `0x4d` and ` 77` named repository 77, and an empty id named 0. `read` refuses an item id without a path, or whose path has an empty, `.` or `..` segment, whose contents address named the repository's root listing or another endpoint. A call whose signal is already aborted throws `GitHubNoAnswer` (`cancelled`). Each refusal is a `TypeError`, except an `Error` for a repository outside the link and the cancel; none quotes a cursor, an item id or a path. A caller that passed several repositories to `changesSince` calls it once per repository, each with that repository's cursor. `read` takes an item whose version is `<blob>@` with no commit after it at the default branch, as it takes one with no version: it sent an empty `ref` and linked a `blob//` address before.
