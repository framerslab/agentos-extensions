Support requests are built: `operations.tickets` holds the person's side (`open`, `list`, `get`, `read`, `write`, `share`, `resolve`, `remove`, `upload`, `picture`, `stream`), staff's side (`staffList` with its counts and 7-day line, `staffGet`, `reply`, `claim`, `setPriority`, `setState`, `openIdentity`, `writeTo`, `staffRemove`, `stats`), `systemMessage` for the product's own events, `hangup` for a product's account deletion step, and `sendDue` and `notifyDue`, which drain the mail and bell outboxes. Each request carries an anonymous id of its own, drawn again on a collision up to five times; the quota and cooldown come from one COUNT; a live stream begins with the request's state and carries each message and state change over `listen` and `notify` on PostgreSQL and a timed read on SQLite; pictures are decoded with sharp and written again as WebP with no metadata; a link to a token path (an address, a `www.` address with no scheme, or a relative markdown destination in every spelling the renderer links, a reference definition indented up to three spaces or inside a blockquote or a list item included, each destination decoded as the renderer decodes it, its escapes and its numeric and named character references, before the cut decides) is cut before it is stored, after the text is cleaned of its control characters, the markdown marks around it kept; `open`, `writeTo` and `systemMessage` ask the directory under the account's lock and refuse an account it does not know or marks deleting, so nothing lands after a deletion, and `reply`, `claim` and `writeTo` do the same for the staff member's own account, so no row names a deleted staff member; `identity(accountId, db)` is given the handle to read through (the write's own transaction there, so a host that reads its own tables inside it never waits on the pool that transaction holds a connection of); the mail and bell drains claim each row before they call a hook (in the process by the module's own set, across processes on PostgreSQL by an advisory lock on the row inside the claim's transaction, a reply's claim then taking the request's own lock and reading its pointers fresh; `mail(message, db)`, `notify(notice, db)` and `staffRecipients(db)` are given the claim's handle to read the product's tables through, as `identity` is, additive for a hook that takes one parameter), so two drains at once deliver each notice once and two replies of one request keep the gap across processes; a mail run's scan starts where the last run stopped and at the oldest row again once a run reaches the end, so rows whose lookup keeps throwing never starve the mail behind them; `stats` counts a category named like a property of `Object.prototype` as its own; `read(actor, id, messageId)` marks the thread read up to the message the page delivered alone, and the stream hook sends that id, so a reply that landed after it and has not reached the page stays unread and is mailed; a person's upload lands under the account's lock with its liveness read fresh, so an account deleted while the decoder ran gets no picture row; a read marker never moves backwards; both lists page from the last request shown; `deleteAccount` and `exportAccount` are built, the export a zip stream with `requests.json` and one file a picture, three a day. The hourly sweep resolves a request after seven days of the person's silence, closes one 30 days after it was resolved and removes uploads no message named within an hour. `./react` holds the headless hooks (the stream hook reads the stream's lines however they end, a CRLF pair split across two chunks included, waits twice as long after each failed connection and stops after a refusal the server will keep giving; a reading hook keys what it read by the client, its fetch and its base, and the path) and the sanitized markdown renderer (http, https and mailto links alone). An actor is a person by its `plan` word or a staff member by its `role` word, never both. The support tables shipped with 0.1.0; no migration is added. One dependency installs with the package, `character-entities`, the table of HTML's named character references the renderer decodes a destination with; every other dependency stays an optional peer. `errors` and `health` still throw `not_built` until the next minor release.
