Support requests are built: `operations.tickets` holds the person's side (`open`, `list`, `get`, `read`, `write`, `share`, `resolve`, `remove`, `upload`, `picture`, `stream`), staff's side (`staffList` with its counts and 7-day line, `staffGet`, `reply`, `claim`, `setPriority`, `setState`, `openIdentity`, `writeTo`, `staffRemove`, `stats`), `systemMessage` for the product's own events, `hangup` for a product's account deletion step, and `sendDue` and `notifyDue`, which drain the mail and bell outboxes. Each request carries an anonymous id of its own, drawn again on a collision up to five times; the quota and cooldown come from one COUNT, a request removed in the last day and the person's messages of the last hour counted with the rows in the process that removed it (no table holds a deleted row, so another process or a restart starts with nothing); a live stream begins with the request's state and carries each message and state change over `listen` and `notify` on PostgreSQL and a timed read on SQLite (on a PostgreSQL pool bounded to one connection no listener is made, since it would hold the only connection and the first read would wait on it for ever: the streams read every 5 seconds instead, with one `ops_listen` line); pictures are decoded with sharp and written again as WebP with no metadata; a link to a token path (an address, a `www.` address with no scheme, or a relative markdown destination in every spelling the renderer links, a reference definition at any indentation or inside a blockquote or a list item included, its destination after a line feed, a carriage return and line feed or a carriage return alone, its label read as the renderer reads it with an escaped bracket or a line ending inside, each destination decoded as the renderer decodes it, its escapes and its numeric and named character references, before the cut decides) is cut before it is stored, after the text is cleaned of its control characters, the markdown marks around it kept; `open`, `writeTo` and `systemMessage` ask the directory under the account's lock and refuse an account it does not know or marks deleting, so nothing lands after a deletion, and `reply`, `claim` and `writeTo` do the same for the staff member's own account, so no row names a deleted staff member; `identity(accountId, db)` is given the handle to read through (the write's own transaction there, so a host that reads its own tables inside it never waits on the pool that transaction holds a connection of); the mail and bell drains claim each row before they call a hook (in the process by the module's own set, across processes on PostgreSQL by an advisory lock on the row inside the claim's transaction, a reply's claim then taking the request's own lock and reading its pointers fresh; `mail(message, db)`, `notify(notice, db)` and `staffRecipients(db)` are given the claim's handle to read the product's tables through, as `identity` is, additive for a hook that takes one parameter), so two drains at once deliver each notice once and two replies of one request keep the gap across processes, and a row one drain holds is passed over by the other and taken up at its next tick; a mail run's scan starts where the last run stopped and at the oldest row again once a run reaches the end, so rows whose lookup keeps throwing never starve the mail behind them; `stats` counts a category named like a property of `Object.prototype` as its own; `read(actor, id, messageId)` marks the thread read up to the message the page delivered alone, and the stream hook sends that id, so a reply that landed after it and has not reached the page stays unread and is mailed; a person's upload lands under the account's lock with its liveness read fresh, so an account deleted while the decoder ran gets no picture row; a read marker never moves backwards; both lists page from the last request shown; `deleteAccount` and `exportAccount` are built, the export a zip stream with `requests.json` and one file a picture, three a day. The hourly sweep resolves a request after seven days of the person's silence, closes one 30 days after it was resolved and removes uploads no message named within an hour. `./react` holds the headless hooks (the stream hook reads the stream's lines however they end, a CRLF pair split across two chunks included, waits twice as long after each failed connection and stops after a refusal the server will keep giving; a reading hook keys what it read by the client, its fetch, its base and its `session` word, and the path, and the stream hook connects again when the client changes) and the sanitized markdown renderer (http, https and mailto links alone). An actor is a person by its `plan` word or a staff member by its `role` word, never both. `./tickets` exports `PICTURE_HEADERS`, the three headers a product's picture route answers with. The support tables shipped with 0.1.0; no migration is added. One dependency installs with the package, `character-entities`, the table of HTML's named character references the renderer decodes a destination with; every other dependency stays an optional peer. A destination or an address is read to its balanced end, so parentheses in balanced pairs (in a destination, escaped ones too) are part of the link and a token behind them is cut with it, the destinations cut before the addresses in running text so an escaped parenthesis never cuts one short; the identity lookup inside a write runs from a savepoint on PostgreSQL, so a statement the directory fails through the handle fails no write, and a claim's hooks have theirs settled once they return, so a hook that swallows its own failed statement counts as failed with the attempt kept, as a hook that throws does; an open still reading when `hangup` or `deleteAccount` ends the actor's or the request's account is refused `not_found` and registers no stream; a `refresh` kept from a request or a client the page has left does nothing; two removals of one request at once delete it once, the second answering `not_found` with nothing remembered for the quota; a statement the database refuses inside one row's send or ring fails that row alone (on PostgreSQL a claim's hooks run from a savepoint, so the attempt counted before a hook's failed statement stays), the run going on to the rows behind it with its lines written; a `pictureOutputBytesMax` above the attachments table's 1,048,576 bytes is refused at `createOperations`; the stream hook keeps its callbacks in a ref written in an effect, never in render. `errors` and `health` still throw `not_built` until the next minor release.
