`repositoriesOfInstallation(credential, installationId)` lists every repository an installation reaches (`GET /installation/repositories`, across every page) with a token that reads their metadata alone, which the credential mints and holds as `metadataToken(installationId)` (`permissions: { metadata: 'read' }`, no repository named). It is the whole of what the app may read through the installation, whoever asks, so a caller finds the repositories an owner took off the app when GitHub's `installation_repositories` delivery names none of them: GitHub sends `removed` with an empty list when an installation goes from all repositories to a selection. A refused token throws `GitHubApiError`, 404 for an installation GitHub no longer has, so a lost installation never reads as one that reaches no repository.

A connector's filter takes `includeCode`: when true, the source files of the new `CODE_EXTENSIONS` (program source in the common languages, shell scripts, SQL, GraphQL and Protocol Buffers schemas, Terraform and style sheets) are kept beside the documentation under the same bounds and skipped folders, each read as UTF-8 text, and a code file a tool wrote is left out (`isGeneratedCode`, by the endings of `GENERATED_CODE_ENDINGS`: minified and bundled files, generated Protocol Buffers and Dart files). It is off when absent, so a filter that does not ask reads documentation alone, as before.
