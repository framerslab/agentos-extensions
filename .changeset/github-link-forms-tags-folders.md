`parseGitHubLink` reads a pasted address as the URL standard reads one, as a browser opens it: the C0 controls and spaces around it are dropped, and every tab and newline in it, and after `http`, `https`, `ws`, `wss` and `ftp` any run of `/` and `\` stands before the host, none included. `https:github.com/acme-team/handbook`, `https:/github.com/acme-team/handbook`, `http:github.com/acme-team/handbook`, `https:\\github.com\acme-team\handbook` and an address with a control character before it answered `null`, so a caller that reads `null` as another site's address read these GitHub addresses as web pages. An address on `ghe.com` or a host under it, where GitHub Enterprise Cloud with data residency serves an enterprise, is `refused`, where it answered `null`.

`resolveRef` settles a tag and a short commit, as github.com serves `/tree/<tag>/` and `/tree/<short commit>/`. When no branch is the text or starts it at a slash, the tags are read (`matching-refs/tags`, the longest tag the same way) and a tag is answered at the commit it names, an annotated tag's object read for it; then a first segment of 4 to 39 hexadecimal characters is read through GitHub's commits under the `application/vnd.github.sha` media type. Both were answered as a branch, and a listing at it threw GitHub's 404. `ResolvedRef` gains `kind` (`branch`, `tag` or `commit`) and `name` (the ref as the link writes it); a tag and a short commit answer `commit: true` with `ref` the whole commit, which `list`, `head` and `changesSince` read as `at`. A first segment no ref name can begin (`a:b`, `a~1`, a control character) is a `TypeError` before any request, where it cost a request and a listing at it threw a `TypeError`, and one that is no branch name and that no branch, tag or commit settles (`-x`, `@`, `end.`) is a `TypeError` after the reads. An address naming a tag by its full name, `refs/tags/<tag>`, stays refused.

`list`, `changesSince`, `listing(repositoryId, commit, { path, signal })` and `planTree` take a `path`: the files of a folder, or the one file a path names, are kept before `maxFiles` counts them. A folder was read by listing the whole repository and keeping the files under it, so in a repository with 2,000 documents sorting before `docs/` a link to `docs` listed nothing, `planTree` answered the folder's files `count`, and `changesSince` answered them gone. A `/tree/` address that names a file lists that file. A `path` with an empty, `.` or `..` segment, or one beside other than one repository in `list`, is a `TypeError` before any request.
